# AGENTS.md - Developer & AI Agent Guide

Welcome, Agent! This repository contains a multi-platform web extension and its automated documentation system. This file serves as your system prompt and operational guide. You must adhere to the rules, structure, and workflows outlined below to ensure consistency, prevent regressions, and preserve code integrity across all platforms.

## 1\. Repository Architecture

The project is structured into three main independent extension variants, a documentation generation system, and helper scripts in the root directory.

```
├── content-analyzer-ext-firefox/   # Firefox Desktop Extension (Self-contained)
│   └── _locales/                   # Localization files
├── content-analyzer-ext-chrome/    # Chrome Extension (Self-contained)
│   └── _locales/                   # Localization files
├── content-analyzer-ext-android/   # Firefox Android Extension (Self-contained)
│   └── _locales/                   # Localization files
├── tpls/                           # Documentation Templates
│   ├── master/                     # Master templates in English (Source of truth)
│   │   ├── template.html           # Main layout wrapper
│   │   └── [other-docs].html       # Document contents (usage, privacy, etc.)
│   └── [lang]/                     # Translated templates (generated by translate.py)
├── docs/                           # Built Documentation (Production)
│   └── [lang]/                     # Final HTML files (generated by gendocs.py)
├── translate.py                    # LLM-based documentation translation script
├── gendocs.py                      # Documentation compilation script
└── toggle_debug.py                 # Debug mode toggler
```

### The Single-Source/Multi-Target Mandate

- **No Shared Code:** There is **no** shared codebase or shared modules folder between the extension variants. Each extension folder is 100% self-contained.
    
- **Strict Replication:** If you modify, fix, or add any feature, script, stylesheet, asset, or library inside one variant, **you must replicate the exact same changes across all three variants** (`content-analyzer-ext-firefox`, `content-analyzer-ext-chrome`, and `content-analyzer-ext-android`).
    
- **Technology Stack:** Every extension is built using **Vanilla Javascript** and standard **HTML/CSS** using the standard **WebExtensions API**. Application frameworks (e.g., React, Vue) or bundlers are strictly forbidden.
    

## 2\. Localization & Translating Documentation (`_locales` & `tpls`)

### Extension Localization

Each extension variant has a `_locales/` folder containing native JSON files for standard WebExtensions localization. If you add new UI elements or messages, you must update the localization JSONs inside the `_locales` directory of **all three extension variants**.

### Documentation Workflow & Editing Rules

The documentation source of truth is written strictly in **English** inside `tpls/master/`.

```
  [tpls/master/] (English Source - Master Copy)
       │
       ▼  (translate.py - On Request Only)
 [tpls/es/], [tpls/de/], etc. (Translated Templates)
       │
       ▼  (gendocs.py - On Request Only)
 [docs/es/], [docs/de/], etc. (Final HTML Docs)
```

#### Important Rules for Editing Documentation:

1.  **Master Copies in English Only:** When asked to add or modify documentation files, you MUST perform all additions and edits exclusively on the files inside `tpls/master/`, writing the content in **English**. Never manually edit files in `tpls/[lang]/` or `docs/[lang]/`.
    
2.  **On-Demand Execution Only:** Do NOT automatically execute `translate.py` or `gendocs.py` after editing documentation templates. These scripts must ONLY be run when explicitly requested by the user.
    
3.  **Environment Check Before Running `translate.py`:**
    
    - Before running `translate.py`, you must check whether the following environment variables exist in the system:
        
        - `TRANS_URL`: Endpoint of the AI service.
            
        - `TRANS_MODEL`: The language model identifier.
            
        - `TRANS_API`: API protocol standard (`ollama` or `openai`).
            
        - `TRANS_API_KEY`: API credential key.
            
    - If any of these variables are missing or undefined, you MUST pause, ask the user to provide their values, and ensure they are set/exported before executing `translate.py`.
        

#### Translation Script Usage (`translate.py`)

- **Execution Modes & Parameters:**
    
    - **Translate Layout:** Run with no arguments to translate only the layout wrapper:
        
        ```
        python translate.py
        ```
        
        *Source: `tpls/master/template.html` -> Dest: `tpls/[lang]/template.html`*
        
    - **Translate Content:** Run with the keyword `all` to translate all templates except the layout wrapper:
        
        ```
        python translate.py all
        ```
        
        *Source: All files in `tpls/master/` except `template.html`*
        
    - **Translate Specific Files:** Pass a space-separated list of filenames:
        
        ```
        python translate.py usage.html privacy.html
        ```
        
    - **Language Target Filtering (`--lang`):** By default, if `--lang` is omitted, the script translates to **all supported languages**. To restrict translation to specific target languages, pass a comma-separated list:
        
        ```
        python translate.py --lang es,de usage.html privacy.html
        ```
        

#### Generation Script Usage (`gendocs.py`)

Once translation is complete and requested by the user, compile the final production documentation:

```
python gendocs.py
```

- **Behavior:** Processes the entire `tpls/` tree. It reads content templates (e.g., `usage.html`), wraps them inside their respective language's `template.html` layout, and outputs the final production-ready HTML files directly into `docs/[lang]/`. This script requires no parameters.

## 3\. Debugging Mechanism (`toggle_debug.py`)

A script named `toggle_debug.py` toggles global debug modes across the project.

- **Usage:**
    
    - To enable debug logging: `python toggle_debug.py on`
        
    - To disable debug logging: `python toggle_debug.py off`
        

### How it Works under the Hood:

The script searches for and replaces the exact string representations of the `DEBUG_MODE` constant in javascript files:

- `const DEBUG_MODE = true;`
    
- `const DEBUG_MODE = false;`
    

### Rules for the Agent:

1.  **Hardcoded List:** `toggle_debug.py` holds a static, hardcoded list of filepaths to modify. It does not scan the workspace dynamically.
    
2.  **Adding New Scripts with Debug Logic:**
    
    - Declare the constant exactly like this (preferably at the top of your Javascript file):
        
        ```
        const DEBUG_MODE = false; // or true
        ```
        
    - **Mandatory Action:** You **must** open `toggle_debug.py` and append the filepaths of your newly created Javascript files (across all three extension directories) to its internal list of targets.
        

## 4\. Policy on Third-Party JavaScript Libraries

While full web frameworks are prohibited, single-purpose external JavaScript libraries (e.g., `turndown.js` for HTML-to-Markdown conversion) may be used when necessary.

### Library Inclusion Rules:

1.  **Self-Contained Priority:** Always give preference to standalone, self-contained libraries that have no external dependencies. If dependencies are required, all dependent scripts must be downloaded and stored directly within each extension folder (no CDN links or runtime fetches).
    
2.  **User Authorization Protocol:** If fulfilling a user task requires installing or downloading a new external JavaScript library:
    
    - **Step 1:** Analyze the required library and identify all of its dependencies.
        
    - **Step 2:** List the target library along with all of its dependencies to the user.
        
    - **Step 3:** Explicitly request user authorization before downloading or installing any library files.
        
    - **Step 4:** Only proceed with downloading and embedding the library if the user grants explicit permission.
        
3.  **Rejection Handling:** If the user denies authorization to install the required library and no alternative implementation exists without it, you MUST inform the user that the requested task cannot be completed.
    

## 5\. Operational Best Practices for Agents

- **Read Before Modifying:** Always inspect existing code in all three extension directories to mimic style, architecture, and vanilla JS idioms.
    
- **Never Fragment Versions:** Treat any ticket/task as a multi-target deployment. Any change must be simultaneously shipped to `content-analyzer-ext-firefox`, `content-analyzer-ext-chrome`, and `content-analyzer-ext-android`.
    
- **Master Documentation First:** Always update documentation exclusively in English within `tpls/master/`. Only execute translation/compilation scripts when explicitly instructed by the user, ensuring environment variables are set first.
    
- **Keep `toggle_debug.py` Synchronized:** Whenever introducing a new script that features debug output, update `toggle_debug.py` immediately.
