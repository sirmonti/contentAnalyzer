1. Arquitectura, Build System y Mantenibilidad

4 Propuestas
#1.1

Sistema de Sincronización y Validación Automatizada entre Variantes

Prioridad Alta Impacto Alto Esfuerzo Bajo
▼

El proyecto sigue un mandato estricto de "No Shared Code" donde cada directorio (content-analyzer-ext-chrome, content-analyzer-ext-firefox, content-analyzer-ext-android) es 100% autocontenido. Sin embargo, replicar cambios manualmente entre las 3 carpetas genera desfases inadvertidos en archivos como options.js, i18n.js, drivers o estilos.

⚠️ Situación Actual

Cualquier bugfix o nueva característica debe copiarse a mano a las tres carpetas. Si se olvida un archivo, se produce divergencia de comportamiento entre navegadores.

✅ Solución Propuesta

Crear un script Python de verificación de paridad (ej. verify_sync.py) que compare hash SHA-256 o AST de archivos comunes (drivers, _locales, estilos compartidos) en el pipeline de CI/CD o pre-commit hook.

scripts/verify_sync.py (Concepto de script de verificación de paridad) Python 
import hashlib, os

SHARED_TARGETS = ["i18n.js", "marked.min.js", "turndown.js", "drivers/openai.js", "drivers/gemini.js"]
VARIANTS = ["content-analyzer-ext-chrome", "content-analyzer-ext-firefox", "content-analyzer-ext-android"]

def verify_parity():
    for target in SHARED_TARGETS:
        hashes = {v: hashlib.sha256(open(os.path.join(v, target), "rb").read()).hexdigest() for v in VARIANTS}
        if len(set(hashes.values())) > 1:
            raise AssertionError(f"Desincronización detectada en {target}: {hashes}")
    print("✅ Todas las variantes están 100% sincronizadas.")

2. Seguridad, Privacidad y Gestión de Credenciales

4 Propuestas
#2.1

Sanitización de HTML y Markdown Renderizado mediante DOMPurify

Prioridad Alta Impacto Crítico Esfuerzo Bajo
▼

En result.js, el contenido devuelto por la IA se procesa con marked.parse(resultText) y se inyecta directamente en resultBox.innerHTML. Si el LLM genera etiquetas <script>, <img onerror=...> o atributos peligrosos debido a una inyección de prompt (Prompt Injection) proveniente de la web analizada, podría ejecutarse código no deseado en el contexto de la extensión.

⚠️ Riesgo de Seguridad

Un atacante que controle el texto de una página web puede incrustar un payload malicioso que obligue al LLM a devolver HTML con vectores XSS ejecutables en result.html.

✅ Solución Propuesta

Incorporar la librería estándar DOMPurify (autocontenida y sin dependencias) antes de volcar el HTML generado al DOM.

result.js (Ejemplo de sanitización segura) JavaScript 
function parseMarkdown(text) {
    const rawHtml = marked.parse(text);
    // DOMPurify elimina scripts, iframes maliciosos y eventos onerror/onload
    return DOMPurify.sanitize(rawHtml, {
        ADD_ATTR: ['target', 'rel'],
        USE_PROFILES: { html: true }
    });
}
#2.2

Enmascaramiento de API Keys en el Interceptor de Depuración (`DEBUG_MODE`)

Prioridad Alta Impacto Alto Esfuerzo Bajo
▼

En background.js y options.js, cuando DEBUG_MODE = true, el interceptor globalThis.fetch captura las cabeceras completas (incluyendo Authorization: Bearer <API_KEY> y x-api-key) y las vuelca en el objeto de error. Si la petición falla, la clave de API completa se muestra en el DOM o en la consola en texto claro.

✅ Solución Propuesta

Sanitizar las cabeceras y los parámetros URL (ej. ?key=AIzaSy... en Gemini) en el interceptor de depuración para mostrar solo los últimos 4 caracteres (ej. Bearer sk-...89aF).

#2.3

Optimización y Granularidad de `host_permissions`

Prioridad Media Impacto Medio Esfuerzo Medio
▼

El archivo manifest.json declara "host_permissions": ["<all_urls>"]. Aunque es necesario para comunicarse con servidores locales de Ollama o endpoints arbitrarios compatibles con OpenAI, los evaluadores de Chrome Web Store y Firefox Add-ons exigen justificaciones muy estrictas para <all_urls>.

✅ Solución Propuesta

Documentar formalmente en el Privacy Policy la necesidad técnica de <all_urls> para conexiones con endpoints autohospedados (Ollama en LAN, LM Studio, etc.) y endpoints cloud configurables por el usuario.

#2.4

Cifrado de API Keys en Almacenamiento Local (`chrome.storage.local`)

Prioridad Baja Impacto Medio Esfuerzo Medio
▼

Actualmente, las claves de API se guardan en texto plano en chrome.storage.local. Aunque el almacenamiento local del perfil del navegador está aislado a nivel de sandbox, ofrecer una clave maestra opcional (Master Key / Web Crypto API) brindaría máxima protección contra accesos locales no autorizados.

3. Rendimiento, Ciclo de Vida y Eficiencia de Recursos

3 Propuestas
#3.1

Throttling y Renderizado por Frames (`requestAnimationFrame`) en Streaming

Prioridad Alta Impacto Muy Alto Esfuerzo Bajo
▼

En result.js, cada vez que llega un fragmento de red (evento chunk), se ejecuta resultBox.innerHTML = parseMarkdown(resultText). En modelos rápidos (Groq, Claude 3.5 Haiku, Gemini Flash) que emiten 50 a 100 chunks por segundo, esto causa que el navegador vuelva a parsear el documento Markdown entero 100 veces por segundo, disparando el uso de CPU y provocando congelamiento visual en textos extensos.

⚠️ Cuello de Botella

Parseo redundante O(N²) durante la generación: cada nuevo token fuerza el re-parseo completo de todos los tokens anteriores y la reconstrucción de todo el árbol DOM.

✅ Solución Propuesta

Sincronizar el re-renderizado con el ciclo de refresco de pantalla mediante requestAnimationFrame o un debounce de 50ms, evitando trabajo innecesario de CPU.

result.js (Optimización de renderizado con rAF) JavaScript 
let renderPending = false;

function scheduleRender() {
    if (renderPending) return;
    renderPending = true;
    
    requestAnimationFrame(() => {
        resultBox.innerHTML = parseMarkdown(resultText);
        resultBox.querySelectorAll('a').forEach(a => {
            a.setAttribute('target', '_blank');
            a.setAttribute('rel', 'noopener noreferrer');
        });
        window.scrollTo(0, document.body.scrollHeight);
        renderPending = false;
    });
}
#3.2

Botón de Cancelación Inmediata de Streaming (`AbortController`)

Prioridad Alta Impacto Alto Esfuerzo Bajo
▼

Actualmente, si el usuario lanza una petición con un prompt erróneo o un texto demasiado largo, no hay ningún mecanismo para detener la generación en curso. La conexión sigue activa consumiendo tokens de pago y ancho de banda hasta que el modelo finaliza.

✅ Solución Propuesta

Añadir un botón "🛑 Detener Generación" en result.html que envíe un mensaje al puerto de background.js para abortar el ReadableStreamReader y cerrar la conexión HTTP inmediatamente.

#3.3

Persistencia Temporal y Recuperación ante Cierre del Service Worker

Prioridad Media Impacto Medio Esfuerzo Medio
▼

En Google Chrome MV3, los Service Workers pueden suspenderse si están inactivos. Aunque el puerto runtime.connect previene la suspensión en la mayoría de los casos, guardar estados intermedios en chrome.storage.session (o local) garantiza que una pestaña de resultados pueda reanudarse sin perder el progreso si la conexión se interrumpe.

4. Integración de Nuevos Motores y Capacidades de IA

4 Propuestas
#4.1

Soporte Nativo para la API de IA en el Navegador (Chrome Built-in AI / Gemini Nano)

Prioridad Alta Impacto Muy Alto Esfuerzo Medio
▼

Los navegadores basados en Chromium incorporan ahora la API estándar Prompt API (Gemini Nano local mediante window.ai o ai.languageModel). Esto permite ejecutar modelos de lenguaje avanzados directamente en el hardware del usuario sin necesidad de instalar Ollama, sin configurar API Keys, sin conexión a Internet y con 100% de privacidad garantizada.

✅ Gran Ventaja Competitiva

  • Cero configuración: Funciona nada más instalar la extensión.
  • 100% Gratuito y Privado: Los datos nunca salen del dispositivo del usuario.
  • Sin latencia de red: Ideal para resúmenes rápidos, traducciones y extracción de entidades.
drivers/chrome_ai.js (Driver para IA local en el navegador) JavaScript 
export async function* generate(config, prompt) {
    if (!window.ai || !window.ai.languageModel) {
        throw new Error("Chrome Built-in AI no está disponible en este navegador.");
    }
    const session = await window.ai.languageModel.create({
        systemPrompt: config.systemPrompt || ""
    });
    const stream = session.promptStreaming(prompt);
    let previousLength = 0;
    
    for await (const chunk of stream) {
        const newContent = chunk.slice(previousLength);
        previousLength = chunk.length;
        yield newContent;
    }
}
#4.2

Soporte Directo para Proveedores Populares: OpenRouter y Groq

Prioridad Alta Impacto Alto Esfuerzo Bajo
▼

Muchos usuarios de extensiones de navegador utilizan OpenRouter (para acceder a cientos de modelos como DeepSeek R1, Llama 3.3, Mistral, Qwen con una sola cuenta) o Groq (por su velocidad de más de 300 tokens/segundo). Aunque ambos son compatibles con el formato OpenAI, tenerlos como opciones preconfiguradas con sus URLs oficiales simplifica enormemente la configuración.

#4.3

Soporte de Modelos Multimodales y Captura Visual (Screenshots / Imágenes)

Prioridad Media Impacto Muy Alto Esfuerzo Medio
▼

Actualmente, el selector interactivo solo extrae texto HTML y lo convierte a Markdown. En la web actual, gran parte de la información clave reside en gráficos, infografías, diagramas y tablas complejas.

✅ Solución Propuesta

Permitir un modo de captura por recorte visual (usando chrome.tabs.captureVisibleTab) y enviar la imagen en Base64 a modelos multimodales (GPT-4o, Claude 3.5 Sonnet, Gemini 1.5 Pro) para análisis visual de diagramas y diseño web.

#4.4

Parámetros de Inferencia Avanzados por Servicio (Temperatura, Top_P, Max Tokens)

Prioridad Media Impacto Medio Esfuerzo Bajo
▼

Diferentes tareas requieren diferentes temperaturas: la extracción de datos JSON o el análisis de código necesitan temperatura 0.0 (determinista), mientras que la redacción creativa o resúmenes se benefician de temperaturas más altas (0.7). Añadir controles de parámetros opcionales en el formulario de servicios mejora drásticamente la calidad de los resultados.

5. Experiencia de Usuario (UX/UI) y Nuevas Funcionalidades

5 Propuestas
#5.1

Integración con el Panel Lateral del Navegador (Side Panel API)

Prioridad Alta Impacto Muy Alto Esfuerzo Medio
▼

Actualmente, cada vez que el usuario ejecuta un análisis, la extensión abre una pestaña nueva en pantalla completa (result.html), obligándolo a alternar constantemente entre la página que está leyendo y el resultado del análisis.

✅ Ventajas del Side Panel

  • Lectura lado a lado: El usuario mantiene la vista en la página web original mientras lee la explicación o resumen en el panel lateral.
  • Soporte en Chrome y Firefox: chrome.sidePanel (Chrome 114+) y sidebar_action (Firefox) están ampliamente soportados.
  • Opción en configuración para alternar entre "Abrir en pestaña nueva" o "Abrir en panel lateral".
#5.2

Chat de Seguimiento Continuo (Multi-Turn Follow-up)

Prioridad Alta Impacto Muy Alto Esfuerzo Medio
▼

Una vez que el modelo devuelve una respuesta, la sesión termina. Si el usuario quiere hacer una pregunta sobre el resultado (ej. "¿Puedes explicar con más detalle el punto 3?" o "Conviértelo a una tabla comparativa"), debe copiar el texto manualmente a otra aplicación.

✅ Solución Propuesta

Añadir una barra de entrada inferior en result.html / Side Panel que mantenga el historial de mensajes de la sesión y permita repreguntar al modelo sobre el contexto capturado.

#5.3

Historial y Biblioteca Local de Análisis con Búsqueda

Prioridad Media Impacto Alto Esfuerzo Medio
▼

Al cerrar la pestaña result.html, el análisis se borra de chrome.storage.local a menos que el usuario lo haya descargado en disco como .md. Incorporar una pestaña "Historial" en las opciones permite revisar análisis previos, buscar por título o dominio y re-exportar en cualquier momento.

#5.4

Botones de Acción Rápida: Copiar al Portapapeles y Resaltado de Sintaxis

Prioridad Alta Impacto Alto Esfuerzo Bajo
▼

En la pantalla de resultados faltan dos utilidades esenciales de productividad:

✅ Acciones Inmediatas

  • Copiar con 1 clic: Botón para copiar el Markdown puro o el texto enriquecido formateado.
  • Resaltado de código (Prism.js / Highlight.js): Coloreado sintáctico automático de bloques ```javascript, ```python, ```html, etc.
#5.5

Ampliación de Etiquetas Dinámicas de Prompt

Prioridad Media Impacto Medio Esfuerzo Bajo
▼

Actualmente se admiten {DATE}, {HOUR}, {URL}, {DOMAIN}, {LANG} y {SYSLANG}. Se recomienda añadir:

🏷️ Nuevas Variables Sugeridas

  • {TITLE}: Título de la página web (document.title).

6. Accesibilidad (a11y) e Internacionalización (i18n)

2 Propuestas
#6.1

Anuncios en Tiempo Real para Lectores de Pantalla (`aria-live`)

Prioridad Media Impacto Alto Esfuerzo Bajo
▼

Durante el streaming, los usuarios con lectores de pantalla (NVDA, JAWS, VoiceOver) no reciben información sobre el estado de la generación. Incluir atributos aria-live="polite" en los contenedores de estado y role="status" asegura una experiencia 100% accesible conforme a las pautas WCAG 2.1 AA.

#6.2

Soporte Completo de Direccionalidad RTL (Árabe y Hebreo)

Prioridad Media Impacto Medio Esfuerzo Bajo
▼

La extensión cuenta con traducciones completas para Árabe (ar) y Hebreo (he) en _locales/. Para garantizar una presentación perfecta, se debe añadir soporte en CSS para html[dir="rtl"], invirtiendo la disposición de la barra lateral, los márgenes de los iconos y las tablas.
